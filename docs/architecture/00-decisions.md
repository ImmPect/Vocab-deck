# Ключевые архитектурные решения (общие для всех разделов ПР3)

Этот файл — единый источник договорённостей. Все разделы отчёта должны им соответствовать.

## Общее
- Приложение: Vocab Deck — веб-приложение для изучения деловой английской лексики A2–B1 в игровой форме (карьерная лестница). ТЗ — отчёт по лабе 2.
- Архитектура: трёхуровневая клиент-серверная. Клиент (SPA в браузере) → REST API (бэкенд) → PostgreSQL.
- Стиль бэкенда: **модульный монолит** (принцип KISS: один разработчик, MVP; модули слабо связаны и при росте нагрузки выделяются в сервисы).
- Хостинг: фронтенд — статические файлы на GitHub Pages / CDN с собственным доменом `app.vocabdeck.ru`; бэкенд — Docker-контейнер на PaaS (Render/Railway) с доменом `api.vocabdeck.ru`; БД — управляемый PostgreSQL. Фронтенд и API — поддомены одного домена, иначе браузер не отправит cookie с SameSite=Lax (разные «сайты»). Запросы клиента — с credentials: include; CORS разрешает только https://app.vocabdeck.ru с Allow-Credentials.

## Бэкенд
- Стек: Python 3.12, FastAPI, SQLAlchemy 2.0 (ORM, параметризованные запросы), Alembic (миграции), Pydantic (валидация), Argon2id (argon2-cffi), Uvicorn.
- Слои внутри каждого модуля: `router` (HTTP, валидация через Pydantic-схемы) → `service` (бизнес-логика) → `repository` (доступ к БД через ORM) → PostgreSQL. Роутер не обращается к БД напрямую.
- Модули:
  - `core` — конфигурация из переменных окружения (12-factor), подключение к БД, безопасность (хэширование, сессии), единый обработчик ошибок, логирование.
  - `auth` — регистрация, вход, выход, сессии, блокировка после 5 неудачных попыток, перенос гостевого прогресса.
  - `users` — профиль, изменение имени/пароля, удаление аккаунта, статистика, достижения пользователя.
  - `decks` — отделы (общие) и личные списки, условия открытия, импорт CSV.
  - `words` — слова: чтение, CRUD в личных списках; для администратора — черновик/публикация/архив.
  - `learning` — раунды мини-игр (генерация вопросов, проверка ответов), входящие, приём ответов (в т.ч. пакетная офлайн-синхронизация), алгоритм Лейтнера.
  - `gamification` — начисление опыта по правилам (табл. 16 ТЗ), должности (табл. 4), серия дней и заморозки, выдача достижений. Внутренний модуль без собственных эндпоинтов: вызывается из `learning` и `auth`.
  - `admin` — эндпоинты администратора (слова общей колоды, отделы, поиск пользователей); проверка роли на каждом запросе.
- Правило: модули общаются только через сервисы друг друга (не через чужие репозитории/таблицы).

## Аутентификация и безопасность
- Сессия: случайный токен в cookie `session_id` с атрибутами HttpOnly, Secure, SameSite=Lax, срок 30 дней; сессии хранятся в таблице `sessions`. JWT не используется (сессию можно отозвать при выходе/смене пароля). API при этом stateless: любое состояние — в БД, любой экземпляр обрабатывает любой запрос.
- CSRF: SameSite=Lax + обязательный заголовок `X-Requested-With: VocabDeck` для изменяющих запросов; CORS разрешён только для origin фронтенда.
- Опыт, должность, ящики и серия вычисляются только на сервере. Клиент передаёт только ответы.
- Гости: могут играть раунды без входа. Сервер проверяет ответ и возвращает подписанную квитанцию `receipt` (HMAC-SHA256 от user-agnostic данных ответа: word_id, direction, mode, is_correct, answered_at, client_event_id). Гостевой прогресс клиент хранит в localStorage как журнал событий с квитанциями. При регистрации/входе журнал отправляется на сервер, сервер проверяет подписи и «проигрывает» события через те же правила начисления (событие без валидной подписи отбрасывается). Так гость не может подделать опыт.
- Rate limiting: вход — 5 попыток / 15 минут на аккаунт (поля users.failed_logins, locked_until) + ограничение по IP на уровне приложения (slowapi).

## Формат API
- Базовый путь: `/api/v1`. JSON, snake_case.
- Успех: `{"data": {...}}`, для коллекций `{"data": [...], "meta": {"page": 1, "limit": 20, "total_items": 45}}`.
- Ошибка: `{"error": {"code": "validation_failed", "message": "...", "details": [{"field": "email", "message": "..."}]}}`.
- Коды: 200, 201, 204, 400, 401 (не вошёл), 403 (нет прав), 404, 409 (конфликт: дубликат почты/слова), 422 (ошибка валидации), 423 (вход заблокирован), 429 (слишком много запросов), 500.
- Пагинация: `?page=&limit=` (limit ≤ 100). Фильтры и поиск — query-параметры.
- Идемпотентность ответов: `client_event_id` (UUID, генерирует клиент) — повторная отправка возвращает тот же результат и не начисляет опыт повторно.

## Перечень эндпоинтов (детализирует раздел API)
Auth:
- POST /auth/register — регистрация (+ необязательный guest_progress)
- POST /auth/login — вход (+ необязательный guest_progress для объединения)
- POST /auth/logout — выход
Текущий пользователь (users):
- GET /me — профиль: имя, роль, xp, должность, до следующей должности, серия, заморозки, число входящих
- PATCH /me — изменить имя / пароль
- DELETE /me — удалить аккаунт и ПДн
- GET /me/stats?from=&to= — ответы по дням
- GET /me/achievements — достижения (полученные и доступные)
Справочники:
- GET /levels — карьерная лестница (должности, пороги, что открывается)
Колоды (decks):
- GET /decks — общие отделы + личные списки пользователя, с прогрессом, признаком locked и условием открытия
- GET /decks/{deck_id} — колода
- POST /decks — создать личный список
- PATCH /decks/{deck_id}, DELETE /decks/{deck_id} — свой личный список
- POST /decks/{deck_id}/import — импорт CSV (multipart) в личный список → отчёт (added, skipped с номерами строк и причинами)
Слова (words):
- GET /decks/{deck_id}/words?page=&limit= — слова колоды (для пользователей — только published)
- POST /decks/{deck_id}/words — добавить слово в личный список
- PATCH /words/{word_id}, DELETE /words/{word_id} — слово своего личного списка
Обучение (learning):
- GET /inbox?direction= — слова, которые пора повторить (next_review_at ≤ сегодня)
- POST /rounds — начать раунд {deck_id, mode: deadline|dictation, direction} → round_id, вопросы (для deadline — 4 варианта), time_limit_s=60
- POST /rounds/{round_id}/answers — ответ на вопрос {question_id, choice_index | text, client_event_id, answered_at, response_ms} → is_correct, correct_answer, xp_awarded, combo, new_box (гостю — receipt)
- POST /rounds/{round_id}/finish — итоги раунда: верных, опыт, повышение (level_up)
- POST /answers/batch — пакет ответов (самооценка на карточках, разбор входящих, отложенные офлайн-ответы) → результат по каждому client_event_id: applied | duplicate | rejected; гостю — receipt по каждому событию без сохранения
Администратор (admin), только role=admin:
- GET /admin/words?q=&deck_id=&status=&page=&limit=
- POST /admin/words — создать (status=draft или published)
- PATCH /admin/words/{word_id} — изменить поля / статус (publish, archive)
- POST /admin/decks, PATCH /admin/decks/{deck_id} — отделы
- GET /admin/users?email= — поиск пользователя
Служебное:
- GET /health — проверка доступности (для мониторинга, NFR-R-05)

## Фронтенд
- SPA: React 18 + TypeScript, сборщик Vite. Маршрутизация — React Router.
- Паттерн: **Flux** (однонаправленный поток данных) в реализации Redux Toolkit: View → action (dispatch) → reducer → store → View. Серверные данные — RTK Query (кэш, повторные запросы, инвалидация). Обоснование: в прототипе уже по сути Flux — единый объект состояния `S`, функции-действия `go()`, `pick()`, перерисовка `render()`.
- Структура кода: Feature-Sliced Design — слои `app`, `pages`, `widgets`, `features`, `entities`, `shared`.
- Локальное хранилище: гостевой прогресс + очередь неотправленных ответов (outbox) в localStorage с номером версии формата (NFR-R-03); при недоступности localStorage — хранение в памяти (NFR-R-01).
- Озвучка: Web Speech API (speechSynthesis), при недоступности кнопка неактивна с пояснением.
- Экраны (из прототипа ЛР2): Приветствие, Кабинет, Карточки, Мини-игра «Дедлайн», Итоги раунда, Регистрация/Вход, Профиль, Входящие, Управление словами (админ) + модальное окно редактирования слова.

## Диаграммы (нотации)
- C4: уровень 1 (Context), 2 (Containers), 3 (Components бэкенда).
- ER-диаграмма БД (нотация «вороньи лапки» или 1/N).
- UML Sequence: раунд «Дедлайн»; регистрация с переносом гостевого прогресса; офлайн-синхронизация ответов.
- Схема компонентов фронтенда и поток данных Flux.
